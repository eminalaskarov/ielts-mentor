# IELTS Mentor

Offline-first PWA that turns the 12-month IELTS plan (Nov 2026 → Nov 2027, B1 → IELTS Academic 7.0+) into a daily guided routine. No backend, no AI, no paid APIs. All data stays in the browser's IndexedDB on the device.

## Stack

- React 19 + TypeScript, built with Vite
- `vite-plugin-pwa` (Workbox): offline cache, update prompt
- Dexie (IndexedDB) with `dexie-react-hooks`
- Vitest for logic and content tests
- Playwright for iPhone-emulated E2E (not in `package.json`, see `e2e/README.md`)

## Folder layout

```
src/
  data/       typed plan data: phases, schedule, checkpoints, milestones, golden rules, resources, band tables, config defaults
  content/    content banks: quiz items, vocabulary, writing and speaking prompts; types.ts is the contract
  logic/      pure logic (Asia/Baku dates, plan resolution, SRS, streak, quiz, backup validation, recovery rules)
  db/         Dexie database (db.ts), backup export/import (backupIo.ts), actions
  features/   screens by area: today, quiz, words, mistakes, writing, speaking, tests, progress, settings, onboarding
  ui/         shared components and icons
  app/        app shell, router, error boundaries
  state/      derived state
  styles/     CSS tokens and app styles
e2e/          Playwright iPhone-emulated E2E script and its README
public/icons/ PWA icons (generated by scripts/gen-icons.py)
scripts/      gen-icons.py
docs/         product and plan documents (see below)
```

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server |
| `npm run build` | Typecheck (`tsc --noEmit`), then `vite build` into `dist/` |
| `npm run preview` | Serves `dist/` on the local network (`vite preview --host`) |
| `npm test` | Runs all Vitest tests (`vitest run`) |
| `npm run typecheck` | TypeScript check only |
| `npm run icons` | Regenerates PWA icons with `python3 scripts/gen-icons.py` |

## E2E tests

See [`e2e/README.md`](e2e/README.md). In short: build, serve `dist/`, then run `e2e/qa-e2e.mjs` against the URL with `webkit`, `chromium` or `all`. The script exits with code 1 if any check fails.

## Content rules

- Item IDs are positional. Arrays in `src/content/` are append-only: add new items at the end, edit existing items in place, never reorder or delete. Progress records reference these IDs.
- `src/content/types.ts` is the contract between the content banks and the app. Change it only deliberately, because both sides depend on it.
- All quiz items, prompts and model answers are original. Books are referenced by title and unit only, never reproduced.

## Database

The Dexie schema is at version 1 (`src/db/db.ts`). Any schema change needs a new `this.version(n+1).stores({...})` with an `upgrade` step, plus a migration test. The current test file `src/db/qa-backup.test.ts` covers only the version 1 open path.
